三、实验原理

1. HTML+CSS+JavaScript 原生开发原理

HTML 负责页面结构搭建，CSS 完成页面样式、布局、卡片、按钮、弹窗、表格等界面效果；JavaScript 实现页面交互逻辑，通过 DOM API 获取、修改页面元素，完成页面渲染、事件监听、表单处理。

本实验不使用任何前端框架，数据与视图分离：业务数据保存在 JS 数组 / 对象内存中，不直接写死在 HTML 标签；封装独立渲染函数，修改数据源之后调用渲染函数重新生成 DOM，完成页面动态更新。

2. localStorage 本地持久化原理

localStorage 是浏览器提供的本地存储 API，仅支持存储字符串类型。对象、数组需要使用 JSON.stringify() 序列化为字符串存入本地；页面加载时使用 JSON.parse() 把字符串还原为 JS 对象数组。数据保存在浏览器本地，刷新网页、关闭浏览器数据不会丢失；清除浏览器缓存、无痕模式下数据会被重置。本实验使用 monthCardData 作为存储 key，多页面共用同一份存储数据源。

3. 多页面与数据联动原理

项目包含 index.html、monthCard.html、addMonthCard.html 三个独立 HTML 文件，页面之间通过 location.href 完成页面跳转。通过 URLSearchParams 读取浏览器 url 查询参数 id，实现新增、编辑复用同一个增加月卡页面；无 id 代表新增，携带 id 代表编辑模式，执行数据回填。所有页面读取同一个 localStorage 存储 key 实现数据共享；月卡数据发生新增、编辑、删除操作后，同步写入本地存储；首页读取月卡数组长度动态计算月卡车辆统计数量，实现页面数据联动更新。

4. 业务模块技术原理

  • 侧边导航菜单：JS 监听点击事件，控制子菜单 DOM 元素 display 属性完成折叠展开；通过 class 切换实现菜单高亮效果。
  • 表单校验：JS 获取表单输入值，对必填项、数字格式、手机号正则、车牌正则、日期合法性做校验，校验不通过在页面输出文字提示，阻止非法数据提交。
  • 前端分页：对原始数组做 slice() 切片截取，根据当前页码、每页条数计算展示数据，实现分页展示、上一页、下一页、切换每页条数。
  • 条件筛选：使用数组 filter() 方法对原始月卡数组做条件过滤，点击查询后重置页码为第 1 页，过滤之后执行渲染函数刷新表格。
  • 复选框全选：JS 监听表头复选框状态，批量修改行复选框 checked 属性，实现全选/取消全选；批量删除根据勾选 id 过滤数组完成数据删除。
  • 日期计算：获取日期输入框的日期对象，计算两个日期时间戳差值，换算得到剩余有效天数；对比结束日期与当前时间，自动判断月卡状态（可用 / 已过期）。
  • 弹窗交互：查看弹窗使用原生 div 模拟遮罩，读取单条月卡对象把全部字段渲染到弹窗内，表单全部设置为只读；续费弹窗复用编辑表单弹窗，仅允许修改缴费相关字段，其他车辆信息字段置为只读；删除使用浏览器原生 confirm() 完成二次确认。

步骤 4：查询筛选与重置功能实现

查询功能：获取车主姓名、车牌号、状态输入值，使用 filter() 对原始月卡数组做条件过滤；点击查询将 currentPage 重置为 1，过滤完成后调用 renderTable() 重新渲染。重置功能：清空表单输入，恢复 filtered = cards.slice() 全部原始数据后重新渲染。

function doFilter() {
  var owner = document.getElementById('filterOwner').value.trim();
  var plate = document.getElementById('filterPlate').value.trim();
  var status = document.getElementById('filterStatus').value;
  filtered = cards.filter(function (c) {
    if (owner && c.ownerName.indexOf(owner) === -1) return false;
    if (plate && c.cardNumber.indexOf(plate) === -1) return false;
    if (status !== '' && Number(c.status) !== Number(status)) return false;
    return true;
  });
  currentPage = 1;          // 查询后重置为第 1 页
  renderTable();
}

步骤 13：自动计算剩余天数与状态

JS 计算开始日期、结束日期时间戳差值，自动计算 remainDay 剩余有效天数；对比结束日期和当前时间，自动设置 status（可用 / 已过期）。日期输入框 onchange 触发 autoCalc() 实时刷新。

function autoCalc() {
  var start = document.getElementById('startDate').value;
  var end = document.getElementById('endDate').value;
  if (start && end) {
    document.getElementById('remainDay').value = calcRemainDay(end);  // 结束日0点 - 今日0点
    document.getElementById('status').value = statusText(calcStatus(end)); // 自动判断
  }
}

function onSave() {

  else { c.id = genId(); cards.push(c); }    // 新增：Date.now() 生成唯一 id

2. localStorage 存储 key 与序列化

var STORAGE_KEY = 'monthCardData';
function loadMonthCards() {
  var raw = localStorage.getItem(STORAGE_KEY);
  if (raw) { try { var arr = JSON.parse(raw); if (Array.isArray(arr)) return arr; } catch (e) {} }
  saveMonthCards(DEFAULT_MONTH_CARDS);           // 写入默认模拟数据
  return JSON.parse(JSON.stringify(DEFAULT_MONTH_CARDS));
}
function saveMonthCards(arr) { localStorage.setItem(STORAGE_KEY, JSON.stringify(arr)); }

八、思考讨论题或体会或对改进实验的建议

1. 数据与视图分离思想的优势

本实验严格遵循"数据驱动视图"思想：业务数据保存在 JS 数组中，不写死在 HTML；任何数据变更都通过调用渲染函数重新生成 DOM。这样做的好处明显——一方面 HTML 结构与业务数据解耦，新增/删除/编辑数据时只需操作数组并调用 renderTable()，无需手动拼接 DOM 节点；另一方面渲染逻辑集中且可复用，减少了直接操作 DOM 带来的状态不一致风险。对比早期"直接把数据写进 HTML 字符串"的做法，数据视图分离让代码更易维护、更易扩展，也为后续理解 Vue/React 等框架的响应式原理打下了基础。

2. localStorage 与多页面数据联动的实现

三个页面通过同一 monthCardData key 共享数据源，实现了"刷新不丢失、多页联动"。其本质是 localStorage 作为浏览器级共享存储，同源页面读取同一份数据。首页月卡车辆总数动态读取数组长度，因此月卡列表的新增/删除操作会立即反映到首页。需要注意的是 localStorage 只能存字符串，对象数组必须 JSON.stringify 序列化、读取时 JSON.parse 反序列化；同时 localStorage 有容量限制（一般 5MB），且数据保存在浏览器本地，清除缓存或无痕模式会丢失，因此仅适合存储少量非敏感业务数据，不宜存储敏感信息或海量数据。

3. 表单校验中正则的作用与边界处理

本实验用正则完成手机号（^1[3-9]\d{9}$）和车牌（省份汉字+字母+4~6 位字母数字）的格式校验，相比逐字符判断，正则更简洁、可读性更强。实践中的体会是：正则的边界处理要细致——例如车牌正则要兼容新能源 8 位车牌（如京AD12345），{4,5} 会误判为非法，需放宽到 {4,6}；同时校验要在"阻止提交"与"用户体验"之间平衡，校验不通过时在字段下方输出文字提示而非粗暴弹窗，更符合现代前端交互习惯。此外前端校验只是第一道防线，不能替代后端校验，仅为提升用户体验、减少无效请求。

4. 对实验的改进建议

  • 可引入 storage 事件监听实现多标签页实时联动（当前需刷新才能看到其他标签页的修改）。
  • 弹窗可优化为拖拽、Esc 关闭、遮罩点击关闭，进一步提升交互体验。
  • 可增加数据导出/导入（JSON 文件）功能，便于备份与跨浏览器迁移。
  • 后续可结合 ECharts 在首页"扩展占位容器"中接入统计图表（如月卡状态分布饼图、收费趋势折线图），让数据概览更直观。
  • 可补充表单"必填星号统一"、"输入实时校验"等细节，进一步向工业级表单靠拢。
